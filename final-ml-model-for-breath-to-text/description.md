# DEAD SILENCE: one-second breath-to-text model handoff

This is the standalone ML component of a spaceship communication game. The player can use a boom microphone close to their mouth to encode messages quietly through deliberate breaths. The teammate's Godot game decides when breath input is allowed. This folder contains the trained one-second model, exactly the recordings used for its training and held-out evaluation, the five-breath mapping and a Python inference bridge. It does not require the original DEAD SILENCE project.

## What to show on screen

Show microphone selection, Start/Stop, current detected class (INHALE, EXHALE or SILENCE), the partial numeric code (at most five digits), the text composed so far, and the complete keyboard reference from `mapping.json`. Display **1 = inhale**, **2 = exhale** and **22121 = delete**. Show that the app needs one second to warm up after starting. Controls to adjust letter, word and send pauses and an explicit Send button are useful. Display microphone errors, audio faults, and whether the game has enabled input. Never hide the keyboard reference during entry.

Every letter uses **five digits**. This mapping is generated by listing 5-digit codes made from 1 and 2 in ascending lexicographic order and assigning the first 26 to A–Z. Example: A = 11111, B = 11112, Z = 22112. Delete = 22121; remaining codes are unassigned. `mapping.json` is the exact machine-readable source of truth. It is not the earlier variable-length letter table. The word pause can accept a suggested word if the game implements that feature.

## What the classifier does

Input: 48 kHz mono float32 microphone audio, split into 2,400 samples (50 ms). A rolling 20-frame buffer represents the latest **one second** and receives a prediction every 50 ms after warmup. Each frame produces six log-power frequency-band features. The classifier takes the per-band mean and standard deviation over those 20 frames (12 values total) and runs a scikit-learn Random Forest. No audio mask, external speaker, cloud key or network inference is needed. The model predicts INHALE, EXHALE and SILENCE (no intentional breath).

Three consecutive matching model predictions are required before the displayed state changes. A digit is emitted when a detected breath state ends or changes; a five-digit code is immediately converted into a letter or delete. A minimum 1-second detected-silence cooldown follows each completed code. After a complete letter, 3 seconds of detected silence emits a word-space event; 5 seconds emits a send event. These gaps are counted from **detected** silence, and the sliding window plus smoothing adds variable detection delay. The initial values are experiments, adjustable via command-line flags. The letter gap is a cooldown, not a delay before committing the letter. Incomplete codes are discarded at the word-gap threshold.

Real-time transition detection and letter accuracy have not been independently validated. Repeated identical breaths require a detectable silence between them to produce separate digits. Background speech, fan noise and audio played through speakers can be misclassified; use headphones and test on the target device. Treat SILENCE as no deliberate breath, not a guarantee of acoustic silence. A sudden discontinuity resets the classifier and partial code.

## Setup and run (Windows)

1. Install Python 3.13 and connect a microphone that supports 48 kHz input. This model was produced with Python 3.13 and the exact versions in `requirements.txt`. The pickle is version-sensitive: match scikit-learn, NumPy and SciPy versions; only open trusted pickle files.
2. In PowerShell, enter this folder and run:

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe stream.py --list-devices
.\.venv\Scripts\python.exe stream.py --device 1
```

Replace `1` with the appropriate listed device index, or omit `--device` to use the OS default. `--list-devices` lists devices only; indices can change between runs. Standard output is newline-delimited JSON; errors go to standard error. Stop with Ctrl+C. If opening the device fails, check OS microphone permissions and that 48 kHz input is supported. Avoid opening the same exclusive device from another app.

To adjust pauses: `stream.py --letter-gap 1 --word-gap 3 --send-gap 5` (seconds; values must be positive and strictly increasing). The classifier is ready after receiving a full second, then emits predictions approximately every 50 ms. `compute_ms` is feature and model compute for that update; it excludes the one-second context and hardware capture latency. `faults` counts callback faults or queue drops. Do not assume `compute_ms` is end-to-end latency.

## Godot integration

Run Python as a local process, for example using `OS.create_process` with an absolute path to the virtual-environment Python and an absolute path to `stream.py`. For a Godot-friendly transport, append `--tcp-port 8765`. Python listens on **127.0.0.1** and waits for one Godot `StreamPeerTCP` connection, then starts the microphone. Retry connecting until the process is ready. Only use a trusted local client. If the TCP connection closes, the bridge exits; terminate the process when leaving the scene. Do not use a blocking call on the game thread to wait for Python.

Read available bytes from `StreamPeerTCP` during `_process`, append their UTF-8 text to a buffer, and parse **complete newline-terminated** JSON messages with `JSON.parse_string`. TCP can split or combine messages: never assume one read equals one message. Example messages:

```json
{"type":"ready","window_ms":1000,"hop_ms":50,"smoothing_frames":3,"letter_gap_s":1.0,"word_gap_s":3.0,"send_gap_s":5.0,"codes":{"11111":"A"},"delete_code":"22121"}
{"type":"prediction","label":"INHALE","raw_label":"INHALE","code":"12","events":[],"silence_s":0.0,"compute_ms":9.2,"faults":0}
{"type":"prediction","label":"SILENCE","raw_label":"SILENCE","code":"","events":[{"type":"letter","value":"A"}],"silence_s":0.05,"compute_ms":9.2,"faults":0}
```

The actual `ready.codes` contains the complete mapping. `prediction.events` may contain multiple events in order: `digit` (value is the partial code), `letter` (uppercase letter), `space` (value null), `delete` (null), `send` (null), `invalid` (unassigned code), and `incomplete` (partial code). Update game-owned text on letter/space/delete; on send, forward the current text to the game's message system. The bridge does not send chat messages, perform text correction, autocomplete or TTS. Those are game-side features and may require separate services. If autocomplete is present, the game may use `space` to accept a visible suggestion; otherwise insert a space. The `reset` event reports a stream discontinuity and clears the partial code. The game should clear its partial-code indicator too. `code` is the current decoder buffer after processing, so it may be empty when a letter event arrives.

`stream.py` also supports stdout JSON Lines without TCP, which is convenient for a separate process supervisor or an integration that supports pipes. Godot's basic `OS.create_process` does not itself provide a stdout pipe; use the TCP option or a suitable process plugin.

## Data, evaluation and retraining

`data/manifest.json` specifies relative WAV paths, their labels, split, source, exact one-second start sample and SHA-256. WAVs are mono 48 kHz. Labels are weak: an inhale or exhale clip can include a pause; no-breath clips are whole-clip intended labels. Original cue clips use seconds 1.1–2.1; newer clips use a centered one-second segment. Recordings shorter than one second were excluded. One segment per recording is used. The split is by recording; some held-out clips were collected close in time to training, so it is not an independent-session guarantee.

The shipped model trained on 38 inhale, 34 exhale and 25 no-breath clips. Offline it scored 20/20 on original held-out breath clips and 21/22 on newer held-out clips (4 inhale, 6 exhale, 12 no-breath). Original held-out clips include no no-breath examples. These small, weak-label results are not continuous typing or real-world accuracy. Details are in `model/evaluation.json`.

```powershell
.\.venv\Scripts\python.exe train_evaluate.py
.\.venv\Scripts\python.exe train_evaluate.py --train
.\.venv\Scripts\python.exe -m unittest discover -s tests
```

The first command evaluates the shipped model; the second retrains with the original hyperparameters and saves `model/retrained_candidate.pkl` without replacing the shipped model. Train/test WAV hashes are checked and duplicates across splits are rejected. For trustworthy future evaluation, gather separately recorded sessions with varied mic placement, background noise, breathing intensity and transitions; label actual events and measure breath-event/letter accuracy, missed and false activations, and end-to-end latency.

This folder intentionally includes raw microphone recordings, which may include voices and background sounds. Review them before sharing or making a repository public. It contains no API keys or `.env` file.
